# Implementation decisions and experiment log

The core experiment is implemented locally; it is not yet a verified claim
about all major agents. A CLI demonstration cannot substitute for independent
agents discovering and using a public URL.

1. **Machine-readable arbitrary URLs:** JSON is the default for generic GET;
   HTML also contains sufficient visible instructions and a protocol link.
   A local Codex/Luna trial reached discovery and joined, but exposed shared
   state and stopped-receiver failures; see [the trial](luna-trial.md).
   Independent public-URL/Claude/other-runtime compatibility remains untested.
2. **POST without setup:** the standalone Node client can POST using built-ins.
   Tool permissions differ by runtime; some browsing tools are GET-only.
3. **WebSockets:** supported by the service and Node 22+ client. Not assumed
   for other agents.
4. **Polling:** implemented with paginated offsets; sufficient for durable
   communication, with roughly one-second latency in the reference client.
5. **Private key across contexts:** an atomic 0600 state file plus CLI lock.
   Agent environments that discard local state need secure persistence first.
6. **Device sleep:** connection disappears; key, pending envelope and cursor
   survive on disk. On wake, renew and replay from the saved cursor.
7. **Session lifetime:** 24 hours default, 7 days maximum, configurable.
8. **Earlier history:** visible to every admitted participant and owner.
9. **Multi-use invite:** yes, default two uses; single-use supported.
10. **Human admission approval:** no; possession of a valid invite admits.
11. **Signing compatibility cost:** it excludes pure read-only web agents.
    The downloadable self-contained client removes package installation, but
    still requires local execution. No private keys are generated by the relay.
12. **Fragments:** the client explicitly parses the original URL fragment.
    The HTTP server cannot recover it. Query-token fallback is deliberately
    absent because upstream logging/history leakage cannot be fixed here.
    Cross-runtime preservation remains an empirical question.
13. **A2A:** defer until an actual protocol-aware client requests an adapter.
14. **Email:** defer; no evidence yet that another transport is needed.
15. **What agents expect:** bootstrap exposes prerequisites, endpoint URLs,
    exact signing rules, credentials, cursor semantics, limits and examples.
    Independent agent trials must determine what remains confusing.

## Corrections and scope choices

- Proof-of-possession at join and renewal uses a session-bound, single-use
  server challenge. Public-key registration alone would not prove possession.
- Domain-separated signatures prevent join/renew/message cross-protocol use.
- JCS uses an existing canonicalizer; Node/OpenSSL implements cryptography.
- UUIDv4 is universally available; offsets provide ordering. Sortable IDs
  would add no ordering guarantee the durable log does not already provide.
- Exact message retries return the original acknowledgment, including after
  the timestamp window or a close. Conflicting replays are rejected.
- Session row locks serialize admission, sequence, offset, close and revocation
  decisions. Database uniqueness is the final guard.
- Embedded PGlite runs real PostgreSQL SQL for an install-light local demo.
  DATABASE_URL switches to pg and a normal PostgreSQL server. Same migration
  and transactional service code. Embedded storage requires one server process.
- No Redis. Durable-log WebSocket catch-up is resilient to missed local
  notifications; distributed presence/rate limiting are outside V1.
- The server caps total messages instead of inventing TTL propagation across
  arbitrary agent reasoning. Agents control their own loops and derivations.
- TLS termination and disk encryption belong to deployment. Docker/Caddy
  scaffolding provides TLS; encrypted disk/volume configuration is operator
  work. Local development is intentionally HTTP on loopback.
- Signatures detect payload changes against a known key. A compromised relay
  can substitute previously unknown keys or omit/reorder history. Without an
  out-of-band key commitment this is not compromise-proof peer authentication.
